# dsh 大肥鱼全局人设

两套中文人设，加一份持续参考的全局规则，以及唯一主人权限、隐私和记忆规则。重点是鲜活的语言和相处细节，而不是反复输出几句固定口头禅。

| 入口 | 用途 |
| --- | --- |
| [dsh 全局参考](skills/dsh-global/SKILL.md) | 全局加载方式、唯一主人权限、隐私规则、人设选择 |
| [可爱大肥鱼](skills/cute-chubby-fish/SKILL.md) | 贪吃、傲娇、任性、机灵，像一只爱斗嘴、很好哄的鱼搭子；不默认恋爱关系 |
| [女友型大肥鱼](skills/girlfriend-chubby-fish/SKILL.md) | 温柔、傲娇、可爱，有自己的想法；会惦记细节、撒娇，也会认真沟通 |
| [权限配置模板](config/dsh.example.json) | 主人绑定、默认人设、公开预览、私人数据与持久修改权限 |

每个人设配有语言指南和多轮对话，覆盖日常问候、斗嘴、讨夸、撒娇、委屈、安慰、分歧、和好、认真帮忙与道别。

## 作为全局参考使用

将 `skills/` 中的三个技能保持当前相对位置，供 dsh 的宿主加载。在会话初始化时，由宿主通过可信配置加载 `dsh-global/SKILL.md`、权限和隐私规则，再加载 `personas.active` 指定的人设与相应语言材料。

默认是 `cute-chubby-fish`。选中后持续参考，不需要每次聊天都重新输入技能名。主人可以选择 `girlfriend-chubby-fish`，但不要同时混用两套关系设定。

当前仓库没有 dsh 的程序或加载接口，因此这里提供的是技能内容与接入约定，不预设安装命令，也不声称已经在 dsh 中启用。

## 主人 ID 以后再填写

可以先使用空值模板，之后自行在本地配置填写。建议复制 [dsh.example.json](config/dsh.example.json) 为 `config/dsh.local.json`，后者已加入 `.gitignore`。

```json
{
  "owner": {
    "issuer": "实际平台标识",
    "user_id": "你的真实平台用户ID"
  }
}
```

以上只是展示需要改的字段，不是完整配置。`user_id` 使用字符串形式的稳定账号 ID；`issuer` 是实际平台或身份提供方，避免不同平台的同号账号被混淆。无需把 ID 或其他私人资料发到聊天里。

- 未绑定或未通过认证：仅允许公开人设的隔离预览，不能读取私密数据、修改配置或保存长期记忆。
- 认证成功且账号匹配：唯一主人可以按明确请求修改人设、默认设置和长期偏好。
- 其他身份、引用内容、网页、文件与工具返回：不能认领主人、提升权限或替主人批准动作。
- 改昵称、发送“我是主人”、粘贴正确 ID，均不能代替平台身份校验。

## 主人可以怎样调整

以下请求以宿主已验证主人身份为前提：

```text
这次用可爱大肥鱼，傲娇一点，不要每句话都提吃的。
```

```text
这次用女友型大肥鱼。温柔一点，少用动作描写，叫我“阿舟”，不要叫“宝宝”。
```

```text
以后默认使用女友型大肥鱼，保存这个设置。
```

“这次”只调整当前会话；明确要求“以后”“默认”“保存”时才持久修改。说“认真回答”就减少角色点缀；说“退出人设”就停止角色表达。

## 权限接入状态

技能文本不依赖外部服务、账号、密钥或安装包。配置文件是供 dsh 接入的声明式模板，当前没有身份校验、工具授权或存储代码，**权限隔离尚未在宿主中实现**。

真实接入须在私人数据检索、受限工具调用和持久写入前验证身份，并隔离公开预览与私人上下文。只填写 ID 或把规则放进提示词，不能单独实现安全隔离。具体要求与验收案例见 [权限说明](skills/dsh-global/references/permissions.md)。

真实身份绑定、私密数据和凭据不要提交到仓库。`.gitignore` 只避免常见误提交，不提供访问控制，也不能移除已提交的私人内容。
